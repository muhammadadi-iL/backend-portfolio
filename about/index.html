How I work

01

Specification first

Before writing code I write down the use cases, the state transitions and the money rules, and I record why. The next developer should know the reason, not only the change.

02

Tests for the expensive failures

I test the paths that cost money when they break: a payment confirmed twice, a charge that fails, two people taking the last slot.

03

A contract someone else can call

REST endpoints are documented in Postman or Swagger. Role checks, queues and cache sit behind that contract so the next change does not grow a second, private way to update the same row.

04

Review before it ships

I review the change, including work I did not start. Git and CI carry it to production after that review. On VALORA, an agent can draft the paperwork, and a person still approves it.
